# 演示成片 · Demo film

演示成片就是网站的**自动浏览**（`?auto`，见 README）：分镜写在网站里（`src/auto/storyboard.ts`），由页面自己逐帧播放。
有两种拍法：

- **用有 GPU 的电脑直接录屏（推荐）**：实时渲染、现场声音，见下文「直接录屏」。
- **`qa/record.mjs` 逐帧拍摄**：在没有 GPU 的机器上也能拍，输出 `qa/video/sunflowers-demo.mp4`：
  **1920×1080 · 30 fps · H.264 High（CRF 21）· AAC 192 kbps 立体声 · 约 68.7 秒**。视频文件体积较大，不入库
  （`.gitignore` 已排除 `qa/video/`），需要时按下文命令重新录制。

## 直接录屏

1. 部署后打开 `https://你的域名/?auto`（本地预览：`npm run build && npx vite preview`，再打开 `http://localhost:4173/?auto`）。
2. 浏览器全屏（16:9 最接近分镜，如 1920×1080），等种子全部点亮。
3. 开始录屏（打开“系统声音/标签页音频”），点「带声音进入」或直接按回车——门页和平时一样，进门后自动浏览开始。
4. 约 64 秒后最后一拍结束，向日葵光标淡出，停止录屏即可。中途按 <kbd>Esc</kbd> 可随时退出；播放期间真实鼠标、滚轮
   和滚动键都被挡住，误碰不会打乱画面，鼠标放在页面里不动即可（系统光标会被隐藏）。

## 怎样拍出来的（`qa/record.mjs`）

- **画面全部是网站真实渲染**：页面是 `dist/` 的正式构建，Chromium（SwiftShader 软件 WebGL）逐帧截图，没有后期合成或剪辑，
  只在首尾各加了 0.6 s / 1.4 s 的淡入淡出。
- **虚拟时钟**（`qa/capture-clock.js`，在任何页面脚本之前注入）：加载阶段时间照常流逝；就绪后冻结，此后只有录制器
  `__cap.step(1000/30)` 才让时间前进——到期的定时器依次触发、跑一帧 rAF、让 React 提交，并把所有 CSS 动画/过渡对齐到同一时刻。
  所以哪怕软件渲染一帧要 3 秒，成片里的每一帧也严格相隔 1/30 秒，动画、滚动和粒子都是匀速的。
- **滚动与光标**：录制器只负责门页——Playwright 发出真实的鼠标事件，移到「带声音进入」并点击（页面带 `?auto`，进门即开始
  自动浏览）。此后的滚动和光标都由页面自己的 `src/auto/autopilot.ts` 播放：滚动按关键帧缓动（经 Lenis
  `scrollTo(…, { immediate })`），光标沿带弧度的贝塞尔路径移动，向光标下的元素派发与真鼠标相同的指针事件；目标点在动作开始时
  从实时布局中取（按钮、色带色块、滑块拇指、花的位置），改版后分镜也不容易错位。自动浏览挂在引擎每帧的开头，所以在虚拟时钟下
  也是严格逐帧推进。
- **声音**：`?capture` 下合成器不出声，而是记下每个音符和开关事件的时间；录完后用同一套 `Synth` 在 `OfflineAudioContext`
  里重新渲染成配乐（`renderSession`），再线性增益到 −18 LUFS——声画严格同步，没有屏幕录音的延迟与噪声。

## 为拍摄做的两处「导演」（如实说明）

1. **加载进度按典型网速的节奏播放**：录制机从本地读取资源，几乎瞬间就加载完，真实进度条会一闪而过；`?capture` 下
   `Loader` 改用 `filmedProgress()`（`src/lib/capture.ts`）——3 秒内先快后慢地填满（字节 82% + GPU 准备 18%）。
   画面仍是网站真实的加载屏和种子动画，只有进度的节奏是设定的。
2. **入口页的箭头光标是叠加的**：网站进门之前没有自定义光标，而截图里不会出现系统光标，所以录制器叠加了一个普通箭头
   和点击光圈（`#cap-cursor`）；进门后它自动隐藏，由自动浏览的向日葵光标接管（点击波纹也是网站自己画的）。

除此之外，`?capture` 不改变网站的任何行为。

## 重新录制

```bash
npm run build
node qa/serve.mjs 4174 dist &
node qa/record.mjs                                              # 正式版 → qa/video/sunflowers-demo.mp4
node qa/record.mjs --fps=10 --dpr=0.5 --out=qa/video-preview    # 分镜预览（约 12 分钟）
```

选项：`--url`（默认 `http://127.0.0.1:4174/`）、`--fps`（30）、`--w`/`--h`（1920×1080）、`--dpr`（WebGL 渲染倍率，预览用 0.5）、
`--out`、`--to=<秒>`（只录前 N 秒）、`--jpeg=<质量>`（帧图质量，默认 93）、`--crf=<x264 CRF>`（默认 21）、
`--no-encode`（只出帧和 WAV）、`--encode-only`（不重拍，只把 `--out` 里已有的帧和 WAV 重新编码，例如换一个 CRF）。
需要 Playwright + Chromium（路径同 `qa/quick.mjs`）和 ffmpeg。

**耗时**：在没有 GPU 的 2 核机器上（SwiftShader 软件渲染），1080p 场景帧约 5–6 秒一帧，正式版约 2060 帧、约 3 小时；
预览（`--fps=10 --dpr=0.5`）约 1 秒一帧，十来分钟。有 GPU 的机器可去掉 `record.mjs` 里的 SwiftShader 启动参数，会快得多。
编码：H.264 High、`preset slow`、`tune film`，声音先测响度再做一次线性增益到 −18 LUFS（两遍 `loudnorm`），首尾淡入淡出。

**改分镜**：编辑 `src/auto/storyboard.ts` 里的 `SCROLL`（滚动关键帧，可写成「某章节 + 若干屏」）、`MOVES`（光标移动 /
路径）、`PRESSES`（按下 → 抬起）和 `END`；改完先跑 `node qa/auto.mjs`（逐个核对每个节拍是否落到位，约 15 分钟），再录屏或
用预览参数拍一遍。`record.mjs` 里只剩门页那几秒（`MOVES` / `BUTTONS` / `TOUR_AT`）。
